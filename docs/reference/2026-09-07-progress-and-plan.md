## 本轮已确认规则及与旧设计的差异

1. 距离倍率在 Casting 实时增长，落水时锁定；取代旧“咬钩时记录距离”的规则。收线不降低倍率。
2. 距离 HUD 显示当前到岸的纵向距离，Reeling 中也更新；不能为保持倍率而冻结 HUD 距离。
3. 原型倍率线性从 1× 增至配置上限，超过目标距离封顶。成功上岸后以基础分乘锁定倍率，四舍五入到整数；结算代码尚待接入。若使用 Mathf.RoundToInt，恰好 .5 的边界采用 Unity 的就近偶数规则，应明确而不是误写成始终向上。
4. PC 改为按住空格蓄力、松开抛竿；移动端保留手势语义输入。蓄力显示使用竖条，仅在键鼠路径蓄力期间出现。
5. 用户认为固定 Flight Duration 生硬，希望时间来自模拟。建议的“初速度+固定角度+重力+虚拟高度”尚未确认；可见腾空弧线是否本轮实现也未得到答复。

## 已发现的具体收尾项

- FishingLoopController.Start 目前只检查 loopProfile，尚未检查新 scoreTuningProfile 引用。
- HandleHookLanded 应使用最终落水距离计算并锁定 CurrentDistanceMultiplier，避免使用最后一次 UpdateCasting 的上一帧值。
- HandleRetrievalCompleted 尚未消费锁定倍率；UI 展示不代表已经加进总分。保留成功上岸一次结算、空钩无分、失败不结算。
- FishingSessionHUD 仍保留 castChargeText；Slider 的 SetActive 写在文字显隐变化条件里。用户最终要求蓄力条，下一次教学应去除不需要的文字依赖，让 Slider 自己判断显隐，保留有效引用。
- 调参目前分散：KeyboardMouseFishingInputSource.Full Charge Duration；FishingHookController.Minimum/Maximum Cast Distance、Flight Duration；ScoreTuningProfile 的距离倍率配置。尚未做统一 Profile 迁移。
- 后续迁移保留实际资产数值并同步所有消费者，删除旧配置来源。现有 CastTuningProfile 同时涉及手势与独立抛竿原型，先核对用途，不能直接混用或用新默认值覆盖。
